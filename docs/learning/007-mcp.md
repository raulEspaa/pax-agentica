# A nation's view over MCP

Spec: [007](../../specs/007-mcp/spec.md). Code: [`mcp_server.py`](../../src/pax_agentica/mcp_server.py).

## What was built

One MCP server with seven read-only tools (the briefing, the compact view, the inbox and the four
calculators of `tools.py`), reached two ways: `pax mcp france --seed 1` over stdio, and `POST /mcp`
on the public tables, where the seat token decides which nation answers.

## What I learned

- **MCP is a wire format for tool calling, not a new kind of tool.** The calculators already had
  JSON schemas for Gemini's function calling (`TOOL_SPECS`); MCP lists the same schema as a tool's
  `inputSchema`, and a call is a JSON-RPC `tools/call` with the arguments. The work was the
  transport and the access control, not the tools.
- **The SDK has two levels.** `MCPServer` (it was called FastMCP before the SDK's version 2) builds
  a tool from a Python function's signature. The low-level `Server` takes two handlers:
  `on_list_tools` and `on_call_tool`. With schemas already written, the low-level server is less
  code and nothing is described twice.
- **Fog of war is an argument you never take.** The server is built with a function from the
  request to a `NationView`: fixed over stdio, the caller's seat over HTTP. No tool has a
  "nation" argument, so there is nothing for a client (or a prompt injection) to change.
- **Authentication sits in front of the protocol.** A small ASGI gate reads the headers, asks the
  lobby's own `table()` and `seat_of()` (the same checks as the web page's endpoints), answers
  401, 403 or 404 itself, and only then hands the request to the MCP transport, leaving the seat
  in the ASGI scope where the tool handler finds it.
- **Stateless Streamable HTTP fits Cloud Run.** With `stateless=True` and JSON answers there is no
  `Mcp-Session-Id` to keep, any instance answers any request, and a client can even call
  `tools/call` with curl and no handshake. The cost: the server cannot send requests back to the
  client (sampling, elicitation), which read-only tools never need.

## What surprised me

- The SDK's transport needs a task group running for the app's whole life: mounted in FastAPI, it
  goes in the app's `lifespan`. A `TestClient` used without `with` never starts it.
- Mounting a sub-app at `/mcp` in Starlette answers `/mcp` with a redirect to `/mcp/`, which MCP
  clients do not follow for a POST; a plain route to the ASGI gate avoids it.
- By default the SDK guards a server on `127.0.0.1` against DNS rebinding by checking the `Host`
  header, which would refuse the Cloud Run hostname. Here the session manager is built directly,
  without that check: the credential is a token in a header, not a cookie a browser would send.

## What I would do differently

- Writing over MCP (`submit_orders`) would be a few lines through `Session.submit`, but read-only
  is a property worth more than the convenience: a leaked token or a confused agent can only read.
- A client like Claude Desktop prefers OAuth for remote servers; a seat token in a header needs the
  `mcp-remote` bridge there. OAuth would be the next step if this became more than a demo.
